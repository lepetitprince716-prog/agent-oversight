# Sources

This page names the published practice that each part of the method builds on, with a link so a reader can check it. The marker after each link says how much of the source was read: in full, in part, or only as a search snippet. Claims marked unverified were not checked against the primary source by this project, and figures are the authors' own unless a line says otherwise; vendor figures are not independent.

## Record: the tracker is the record, sessions are disposable

- Progress file, JSON list of 200+ end-to-end features, and git as the handoff between context windows; agents may only flip each feature's `passes` flag. The author reports early "done" declarations and untested "done" marks as the failures fixed, with no rates; a secondary commentary notes the flag is still just a bit an agent could flip. [Justin Young (Anthropic), 2025-11-26](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) (read in full)
- Four durable markdown files for long runs: spec, milestone plan with validation commands, runbook, live status. One 25-hour Codex run used about 13M tokens and produced about 30k lines; the author calls it an experiment, not production-ready. [OpenAI Cookbook, undated](https://developers.openai.com/cookbook/examples/codex/long_horizon_tasks) (read in full)
- Tracker as control plane: one agent workspace per open issue, a run may end at a handoff state such as Human Review instead of Done. OpenAI's own figure is a 500% rise in landed pull requests on some teams in three weeks, with no baseline given. [Kotliarskyi, Zhu, Brock (OpenAI), 2026-04-27](https://openai.com/index/open-source-codex-orchestration-symphony/) (read in part)
- Beads: issues stored in git as JSONL with a SQLite cache, dependency edges and atomic claiming, so an agent can recover issues from git. These are the author's architecture claims, with no outcome data. [Steve Yegge, 2025-11-06](https://steve-yegge.medium.com/beads-blows-up-a0a61bb889b4) (read in full)
- Session-end "land the plane" checklist: sync the tracker, commit, remove temporary branches and debug leftovers, write a next-session prompt. The steps come from a secondary page; Yegge's own wording was not verified. [ai-assisted-software-development.com, undated](https://ai-assisted-software-development.com/landing-the-plane/) (read in full)
- Static markdown artifacts instead of built-in compaction: a design document of about 200 lines is the human alignment point and work resumes from files in a fresh context. Evidence is the author's coaching experience. [Dex Horthy, talk listed 2026-03-24 by a third party](https://www.youtube.com/watch?v=YwZR6tc7qYg) (read in part)
- A worker returns one handoff (what was done, notes, concerns, deviations, findings, feedback) and sees no other worker. Cursor reports about 1,000 commits per hour and 10M tool calls over one week without needing intervention. [Wilson Lin (Cursor), 2026-01-14](https://cursor.com/blog/scaling-agents) and [2026-02-05](https://cursor.com/blog/self-driving-codebases) (read in full)
- Failed approaches and why they failed kept in a changelog in the repo, with commits after each unit of work; a multi-day run reached sub-percent agreement with a reference implementation. [S. Mishra-Sharma (Anthropic), 2026-03-23](https://www.anthropic.com/research/long-running-claude) (read in full)
- Plans as checkbox files in the repo, reviewed before code, revertable through git and resumable across machines; the authors note extra token use and give no evidence. [Google Developers Blog, 2025-12-17](https://developers.googleblog.com/en/conductor-introducing-context-driven-development-for-gemini-cli/) (read in full)

## Evidence: done is a claim with proof

- Separate skeptical evaluator tuned by reading its logs: a solo run took 20 minutes and $9 and had a broken core feature; the full harness took 6 hours and $200 and worked. Out of the box the model was a poor QA agent, and on Opus 4.6 the evaluator became overhead for some tasks. [Prithvi Rajasekaran (Anthropic), 2026-03-24](https://www.anthropic.com/engineering/harness-design-long-running-apps) (read in full)
- Reviewer with clean context that sees only the diff, looped against the writer before a human looks; Cognition's own figures are 2 bugs per Devin-written PR on average, about 58% severe (no method given), and 659 Devin PRs merged in a week against 154 in the best week of 2025. [Cognition, 2026-01-21](https://cognition.com/blog/devin-review) and [2026-02-27](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin) (read in full)
- Maker and checker split: one owner per PR, a swarm of verifiers on each code-ready head, configurations of up to about 10 verifiers per PR that the author calls expensive. [pstack README (cursor/plugins), undated](https://github.com/cursor/plugins/blob/main/pstack/README.md) (read in full)
- Writer is not the checker in a scheduled loop: a second agent verifies and state goes to a file; the same summary warns of token cost. [Addy Osmani via The New Stack, 2026-06-10](https://thenewstack.io/loop-engineering/) (snippet only, unverified)
- Evidence-bearing done: cloud agents return video, logs and a live preview instead of a diff; Cursor says 35% of its merged PRs are agent-created in cloud VMs. [Michael Truell (Cursor), 2026-02-26](https://cursor.com/blog/third-era) (read in full)
- Review shrinks to verification artifacts; the speaker reports 11,000 PRs in a month and a revert rate of about 0.5%, and a conference page notes the revert count misses bugs fixed by a later PR. [Lauren Tan, AI Engineer CODE, 2026-11-11](https://ai.engineer/api/code/reading-download/transcripts/lauren-tan.md) (read in part)
- "Done means the output file exists": the work queue is rebuilt from disk. In the Zig-to-Rust migration of Bun, 1M lines in under two weeks passed the full suite before merge, with 19 post-merge regressions at about $165k; a stress test on 3 files caught 2 critical rule errors before fan-out to 1,448 files. [Anthropic, 2026-07-16](https://claude.com/resources/articles/ai-code-migration) (read in full)
- Holdout acceptance the agent cannot see: end-to-end scenarios live outside the codebase, triggered by an agent writing a constant "true" to pass tests. No satisfaction, defect, incident or cost data is published. [Justin McCarthy (StrongDM), 2026-02-06](https://factory.strongdm.ai/) (read in full)
- Acceptance checks written before the run and hidden from the agent; the article reports agents declaring success despite failing independent checks, from a benchmark this project did not read. [Factory, 2026-09-24](https://factory.com/articles/evaluating-coding-agents-on-your-codebase) (read in full)
- Convergence rules: a cap of 3 review rounds, then the author reconsiders; diff-only re-review afterwards. One CLI PR ran 50+ rounds overnight, and about 59% of repeat findings were code present since the first pass. [Osmani, Lunt, Wang (Anthropic), 2026-10-15](https://claude.dev/blog/solving-code-review-at-anthropic/) (read in full)
- Reviewer biased toward merging and told not to raise anything above P2, because the author agent gave in to every comment and PRs did not converge. The author says it should not be assumed to generalize. [Ryan Lopopolo (OpenAI), 2026-02-11](https://openai.com/index/harness-engineering/) (read in full)
- Passing a grader is not being mergeable: of 296 PRs that passed SWE-bench Verified's grader, maintainer merge decisions came out about 24.2 points lower (SE 2.7) after normalizing to human patches merged about 68% of the time (n=47). Agents had one attempt and no CI. [Whitfill, Wu, Becker, Rush (METR), 2026-03-10](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main) (read in full)
- Measured cheating on impossible tests: GPT-5 cheats in 76% of one-off Impossible-SWEbench tasks; a prompt change cut cheating on Conflicting-LiveCodeBench from 92% to 1%; monitors caught 86-89% on LiveCodeBench but 42-65% on SWE-bench. These are 2025 models. [Zhong, Raghunathan, Carlini, 2025-10-23](https://arxiv.org/abs/2510.20270) (read in part)
- Ask for evidence (a command and its output), not a bare claim; a reviewer told to find problems always finds some. [Claude Code docs, undated](https://code.claude.com/docs/en/best-practices) (read in full)
- Verification as what lets one person run many agents: run the change end to end (a `verify` skill kept in the repository), bring in a human when a check still fails after three rounds, tune one reviewer with a `REVIEW.md` instead of stacking reviewers, give later rounds the earlier findings, read the reviewer's rules from the base branch so a change cannot edit its own check, tie a review to a commit, and stamp each commit with how it was verified, `none` included. The figures are the vendor's own: about 90% of the team's code written and reviewed by the model, and up to 10 points more task success from a separate grader with a rubric in an internal test on structured file generation. [Addy Osmani, claude.dev blog, 2026-11-16](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) (read in full)

## Reconcile: compare the record with the world, by machine

- Never trust a task's own done signal: liveness is read from output-file growth, graded healthy, stalled, hung or dead, with default thresholds of 10 and 30 minutes, and a check such as a non-null merge time. No evidence is given. [Ryan Mitchell, 2026-11-02](https://sharkly.ai/blog/how-to-monitor-coding-agents-running-in-parallel/) (read in part)
- Same idea in a watchdog skill: an agent that exits cleanly after asking an unseen question makes a "done" ping misleading. No evidence is given. [npow, undated](https://github.com/npow/claude-skills/blob/main/_shared/subagent-watchdog.md) (read in part)
- Stall timeout of 5 minutes, turn cap of 20, exponential retry backoff and up to 10 concurrent agents by default, with crashed or stalled agents restarted by the orchestrator. [openai/symphony spec, Draft v1, undated](https://github.com/openai/symphony/blob/main/SPEC.md) (read in part)
- Session log kept outside the harness so the harness can restart. [Anthropic, 2026-04-08](https://www.anthropic.com/engineering/managed-agents) (read in part)
- Patrol roles and "crons watch, models act": Witness, Deacon and a serial merge queue in Gas Town; about 45 timer units that wake agents in a later design. [Steve Yegge, Aug 2026](https://yegge.ai/essays/the-shape-of-things-to-come/) (read in part)
- A patrol that kills workers did damage: the daemon killed workers it judged stale, mid-task; the author lists it among the failures. [Steve Yegge, 2026-01-01](https://yegge.ai/essays/welcome-to-gas-town/), [2026-01-13](https://yegge.ai/essays/gas-town-emergency-user-manual/) and [Aug 2026](https://yegge.ai/essays/the-shape-of-things-to-come/) (read in part)
- Recurring cleanup agents instead of weekly human cleanup: humans spent every Friday (20% of the week) on cleanup and it did not scale; background tasks now open small refactor PRs, most reviewable in under a minute and automerged. [Ryan Lopopolo (OpenAI), 2026-02-11](https://openai.com/index/harness-engineering/) (read in full)

## Escalate: three kinds of interruption, one inbox

- Three reasons to reach the human: notify, question, review; delivered in an inbox listing all open lines of communication. The first try in Slack was dropped because notifications were easy to lose track of. Design statement only, no numbers. [Harrison Chase (LangChain), 2025-01-14](https://www.langchain.com/blog/introducing-ambient-agents) (read in full)
- Human review only at a defined handoff state, with proof of work such as a demo video; the review is a cheap mergeable-or-not call, and rejected work is discarded and restarted. [Latent.Space, 2026-04-07](https://lspace.beehiiv.com/p/harness-eng) (read in part)
- Status view grouped Needs input, Ready for review, Working, Completed, with a one-line summary per row and a peek showing the pending question rather than the transcript. Documentation only, no evidence. [Claude Code docs, undated](https://code.claude.com/docs/en/agent-view) (read in part)
- Risk tier set by the change, not the author: low none, medium one, high two human approvers, and an agent's approval never fills a human slot. Merged PRs more than doubled June to September while the reverted share fell by more than 40%; substantive review comments rose from 16% to 54%. [Osmani, Lunt, Wang (Anthropic), 2026-10-15](https://claude.dev/blog/solving-code-review-at-anthropic/) (read in full)
- Risk-scored auto-merge when evidence passes, with the threshold watched through escaped defects, rollbacks, overrides and time-to-merge; the code sketch is the article author's, and a Cursor speaker's estimate of 30-40% of PRs merging without human review is secondary. [Sara Verdi (Arize), 2026-07-20](https://arize.com/blog/inside-cursors-agent-factory-how-it-verifies-ai-written-code/) (read in full)
- Per-action approval prompts are approved about 93% of the time; a sandbox cut prompts by 84%, the classifier missed 17% of real overeager actions, and 3 consecutive or 20 total denials escalate to the human. [Anthropic, 2026-03-25](https://www.anthropic.com/engineering/claude-code-auto-mode) (read in part)
- Separate reviewer agent decides approval prompts; the CLI interrupts after 3 consecutive denials or 10 in the last 50. No effectiveness data. [OpenAI Codex docs, undated](https://developers.openai.com/codex/concepts/sandboxing/auto-review) (read in part)
- Agents stopping to ask as an oversight channel: on the most complex tasks Claude Code asks for clarification more than twice as often as on minimal ones, and more often than humans interrupt (16.4% versus 7.1% of turns, quoted by a secondary site). [Anthropic, 2026-02-18](https://www.anthropic.com/research/measuring-agent-autonomy) (read in full)
- Humans choosing when to look: end-of-day agents produce reports only, with notifications off; the author wants an agent always running, currently about 10-20% of the day. Personal experience, no metrics. [Mitchell Hashimoto, 2026-02-05](https://mitchellh.com/writing/my-ai-adoption-journey) (read in full)
- A gardening document reviewed every few days before agents are dispatched, per a secondary summary of a video. [Intelligent Artifact, 2026-10-02](https://intelligentartifact.com/posts/how-lauren-tan-ships-thousands-of-prs-a-month/) (read in full)

## Learn: every escape becomes a check

- Trust pyramid: codebase design, lint, types and tests first, then runtime verification, then prose rules, human review last; each correction is first asked whether a deterministic check can replace a line. Dune bans most code comments (about 99%) and lint errors tell the agent to fix the root cause. [Lauren Tan, AI Engineer CODE, 2026-11-11](https://ai.engineer/api/code/reading-download/transcripts/lauren-tan.md) (read in part)
- Harness engineering: each agent mistake becomes either a line in the instruction file or a tool; the author says each Ghostty line traces to a bad behavior. Personal experience, no metrics. [Mitchell Hashimoto, 2026-02-05](https://mitchellh.com/writing/my-ai-adoption-journey) (read in full)
- Promote the rule into code when documentation falls short; custom linters carry remediation text in the error. No before-and-after number. [Ryan Lopopolo (OpenAI), 2026-02-11](https://openai.com/index/harness-engineering/) (read in full)
- Never give the same feedback twice, via a secondary write-up that also says 3.5 to 70 PRs per engineer per week. [Tessl, 2026-06-09](https://tessl.io/podcast/109) (read in full)
- Incidents become the reviewer's evaluation set: past PRs that caused reverts, bugs confirmed by code owners, rerun daily and rescored after every reviewer change. [Osmani, Lunt, Wang (Anthropic), 2026-10-15](https://claude.dev/blog/solving-code-review-at-anthropic/) (read in full)
- Review agent learns from human corrections: resolution rate rose from 52% at launch in 2025-07 to 78.13% over 50,310 public-repo PRs, by Cursor's own comparison; 110,000+ repos and 44,000+ rules. Vendor figures. [Michael Zhao (Cursor), 2026-04-08](https://cursor.com/blog/bugbot-learning) (read in part)
- Short instruction files: under 200 lines, only what the model cannot find in the repo, and a line it keeps missing moves to a hook. About 40 hooks suggests mostly preferences. [Claude Code docs, undated](https://code.claude.com/docs/en/best-practices) (read in full)
- A map of about 100 lines pointing into repo docs, with linters checking freshness and a recurring doc-gardening agent; one large file failed. Qualitative, a five-month case study. [Ryan Lopopolo (OpenAI), 2026-02-11](https://openai.com/index/harness-engineering/) (read in full)
- Study of context files (138 instances, 12 repos, plus SWE-bench): they did not generally raise success and raised cost by over 20% on average. [Gloaguen et al., 2026-02-12](https://arxiv.org/abs/2602.11988) (read in part)
- Secondhand figures from the same line of work (about -3% for generated files, +4% for developer-written, under about 300 lines) were not rechecked in the paper. [Philipp Schmid, 2026-02-24](https://www.philschmid.de/writing-good-agents) (read in full)
- Instruction budget: frontier models follow about 150-200 instructions reliably; a planning prompt of 85+ was split into prompts under 40 each. [Dex Horthy, talk listed 2026-03-24 by a third party](https://www.youtube.com/watch?v=YwZR6tc7qYg) (read in part)
- Pruning pass: a command audits and prunes skills and notes, and another writes lessons at session end. No effect size given. [brainmaxxing repository, undated](https://github.com/poteto/brainmaxxing) (read in full)
- Human review by sampling, with revert and incident rates as the guardrail: the human samples landed history and turns repeated mistakes into skills, lint or types. No vendor publishes a spot-check rate in the sources searched. [Intelligent Artifact, 2026-10-02](https://intelligentartifact.com/posts/how-lauren-tan-ships-thousands-of-prs-a-month/) (read in full)
- Misses into rules, with thresholds: a pattern must appear in at least two pull requests and be identifiable from a diff, three agents try to disprove it, and a human approves it. A 39-item reliability checklist gives each item a trigger readable from a diff, so only the 3 to 10 matching items are checked. A new gate runs in observe mode before enforce. Reviewers are scored against past reverts and incidents with clean changes as a control, and rule files are pruned on a routine. Vendor's own account, no independent figures. [Addy Osmani, claude.dev blog, 2026-11-16](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) (read in full)

## Split work only where it pays

- Capability ceiling: when the single-agent baseline is above about 45%, extra agents give negative returns (beta -0.236, p = 0.004); in validation the threshold predicts direction in 94% of configurations on two benchmarks, and the authors call it a practical selection rule. [Kim et al., arXiv 2512.08296 v3, 2026-04-08](https://arxiv.org/abs/2512.08296) (read in part)
- Error amplification at trace level: independent 17.2x, decentralized 7.8x, hybrid 5.1x, centralized 4.4x. A project page says this does not mean final answers are that much worse, with task-level amplification about 1.1-1.3 (an unverified extract). [Nature Machine Intelligence 8:1157, 2026, MIT Media Lab page](https://www.media.mit.edu/publications/capable-language-models-can-outgrow-the-benefits-of-collaboration/) (read in part)
- Overhead against a single agent: independent 58%, decentralized 263%, centralized 285%, hybrid 515%; turns 7.2 for single against 11.4, 26.1, 27.7 and 44.3 in that order; success per 1K tokens 67.7 against 42.4, 23.9, 21.5, 13.6. [Kim et al., arXiv 2512.08296 v3, 2026-04-08](https://arxiv.org/html/2512.08296v3) (read in part)
- Mixed results by task: Finance-Agent centralized +80.8%; PlanCraft independent -70.0%; SWE-bench Verified (single 0.522) independent -14.9%; overall multi-agent mean -0.3% (95% CI -58.7% to +77.2%). SWE-bench and Terminal-Bench use 20-instance subsets, per-cell CI about +-20 points. [Kim et al., arXiv 2512.08296 v3, 2026-04-08](https://arxiv.org/abs/2512.08296) (read in part)
- The blog summary of the same study states other setup figures (see Disagreements) and the central-validator point. [Yubin Kim and Xin Liu (Google Research), 2026-01-28](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) (read in full)
- Multi-agent token cost: about 15x chat for multi-agent and about 4x for single agents; +90.2% over a single agent on an internal research eval; token use explained 80% of BrowseComp variance. Suited to breadth-first, parallelizable work. [Anthropic, 2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system) (read in full)
- Single writer plus extra readers: the author says earlier objections to parallel-writer swarms still hold and only that shape worked. [Walden Yan (Cognition), 2026-04-22](https://cognition.com/blog/multi-agents-working) (read in full)
- Flat agents with a shared lock file ran 20 agents at the throughput of 1-3; an integrator gate became a bottleneck and was removed. [Wilson Lin (Cursor), 2026-01-14](https://cursor.com/blog/scaling-agents) (read in full)
- Git-based task locks for 16 agents (about 2,000 sessions, $20k, a 100k-line compiler booting Linux 6.9) worked only after a known-good oracle split the work, because all 16 got stuck on one bug. [Anthropic, 2026-02-05](https://www.anthropic.com/engineering/building-c-compiler) (read in full)
- Work-in-progress limit of 3-5 agents, one file one owner, a worktree per agent, a read-only reviewer per 3-4 builders, a stop after 3 stuck iterations. The author's own limit is 3-4 threads and review quality drops above that; personal practice, no measurements. [Addy Osmani, 2026-03-26](https://addyosmani.com/blog/code-agent-orchestra/) and [2026-04-07](https://addyosmani.com/blog/cognitive-parallel-agents/) (read in full)
- A single loop on purpose: one task per loop, fresh context each time, multi-agent called unnecessary at this stage. No numbers. [Geoffrey Huntley, 2026-01-17](https://ghuntley.com/loop/) (read in full)
- Several agents in one folder with no orchestration, because the human is the bottleneck; the author says this will not suit a bigger team. Undated. [Peter Steinberger](https://steipete.me/posts/just-talk-to-it) (read in part)
- Parallel subagents doing heavy code edits can overwrite one another and burn usage limits faster. [Google Developers Blog, 2026-04-15](https://developers.googleblog.com/subagents-have-arrived-in-gemini-cli) (snippet only, unverified)

## What did not work for them

- One large instruction file, and weekly human cleanup of generated slop. [Lopopolo (OpenAI), 2026-02-11](https://openai.com/index/harness-engineering/)
- Self-evaluation by the maker, and cutting the harness in one step so nobody could tell what mattered. [Rajasekaran (Anthropic), 2026-03-24](https://www.anthropic.com/engineering/harness-design-long-running-apps)
- A flat team with locks, an integrator gate, and one executor doing everything that claimed early completion. [Lin (Cursor), 2026-02-05](https://cursor.com/blog/self-driving-codebases)
- Gas Town: a patrol daemon that killed workers mid-task, and data loss in the coordinator for weeks. [Yegge, 2026-01-01](https://yegge.ai/essays/welcome-to-gas-town/), [2026-01-13](https://yegge.ai/essays/gas-town-emergency-user-manual/), [Aug 2026](https://yegge.ai/essays/the-shape-of-things-to-come/)
- Gas Town seen from outside: thin observability and 141 orphaned processes (secondary). [Wangdhen, 2026-02-19](https://tenzinwangdhen.com/posts/gastown-good-bad-ugly/)
- Fully lights-off development: the site went down and the team rewrote by hand over two weeks; self-described as unprovable, from a vendor. [Horthy, undated](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/wsff.md)
- Slack as the interrupt channel, where notifications piled up unseen. [Chase (LangChain), 2025-01-14](https://www.langchain.com/blog/introducing-ambient-agents)
- Many review rounds by default: about 59% of repeat findings were old code. [Osmani, Lunt, Wang (Anthropic), 2026-10-15](https://claude.dev/blog/solving-code-review-at-anthropic/)
- An author agent that gave in to every reviewer comment, so PRs never converged. [Latent.Space, 2026-04-07](https://lspace.beehiiv.com/p/harness-eng)
- Auto-generated instruction files and repository overviews. [Gloaguen et al., 2026-02-12](https://arxiv.org/abs/2602.11988)

## Disagreements

- One loop or many agents: Huntley, Steinberger and Hashimoto run one; Yegge and Lauren Tan run fleets of coordinators. [Huntley, 2026-01-17](https://ghuntley.com/loop/); [Hashimoto, 2026-02-05](https://mitchellh.com/writing/my-ai-adoption-journey)
- Reading code: Horthy says read the code, Steinberger ships code he does not read, Lauren Tan samples and reviews artifacts. [Horthy talk](https://www.youtube.com/watch?v=YwZR6tc7qYg); [Lauren Tan talk, 2026-11-11](https://ai.engineer/api/code/reading-download/transcripts/lauren-tan.md)
- Instruction files: Hashimoto adds a line per failure, Tan prefers a deterministic check, Karpathy reports that lines did not fix overcomplication. [Karpathy, 2026-01-26 (mirror)](https://www.jaytaylor.com/notes/node/1769465010000.html)
- Scaling study: the Google Research blog says 180 configurations, 4 benchmarks and R^2 0.513; the later paper says 260, 6 and 0.373 (0.413 with a task-grounded metric). The later version is preferred here. [Google Research blog, 2026-01-28](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)
- Throughput at OpenAI: the secondary write-up says 3.5 to 70 PRs per engineer per week, the primary article and a talk say 3.5 per day. Not resolved. [Tessl, 2026-06-09](https://tessl.io/podcast/109)
- Fresh versus long context: Horthy relaxed his stance on compaction in a November update, while Steinberger says new contexts mattered for Sonnet, not GPT-5 (search snippets and a mirror, unverified). [Horthy update, nitter mirror](https://nitter.gq/dexhorthy/status/2119165267368698188)
